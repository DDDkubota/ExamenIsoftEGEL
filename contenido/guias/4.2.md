# 4.2 Calidad de software (10 reactivos)

## Calidad del proceso, del producto y en uso
| Objeto | Modelos / normas |
|---|---|
| **Proceso** | **CMMI**, **MoProSoft** (NMX-I-059-NYCE, México), **ISO/IEC 29110** (entidades muy pequeñas), ISO 9001 / ISO 90003, SPICE / ISO 33000, TSP/PSP |
| **Producto** | **ISO/IEC 25010:2023** (9 características), familia SQuaRE (ISO/IEC 25000; la guía cita **25002:2024**) |
| **En uso** | Efectividad, eficiencia, satisfacción, ausencia de riesgo, cobertura del contexto |

## CMMI: niveles de madurez
1. Inicial (caótico) · 2. **Gestionado** (por proyecto) · 3. **Definido** (estándar organizacional) · 4. **Gestionado cuantitativamente** (estadística) · 5. **En optimización** (mejora continua)

## SQA, V&V y técnicas
- **Verificación**: ¿construimos el producto *correctamente*? (contra la especificación)
- **Validación**: ¿construimos el producto *correcto*? (contra las necesidades del usuario)
- Revisiones técnicas formales, inspecciones (Fagan), walkthroughs, auditorías
- Gestión de la configuración (líneas base, control de cambios)
- Herramientas: diagrama de Ishikawa (causa-efecto), Pareto (80/20), histogramas, **benchmarking** (comparar con referentes o con proyectos anteriores)

## Métricas
- **Densidad de defectos** = defectos / KLOC
- Complejidad ciclomática V(G) = E − N + 2 = decisiones + 1
- Eficiencia en la eliminación de defectos: DRE = E / (E + D)
- MTBF, MTTR, disponibilidad = MTBF / (MTBF + MTTR)
- Cobertura de pruebas, acoplamiento (CBO), cohesión (LCOM), profundidad de herencia (DIT)
- GQM (Goal-Question-Metric) para definir las métricas
