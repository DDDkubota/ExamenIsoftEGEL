# 2.2 Diseño de módulos, componentes y datos (16 reactivos, la subárea con más peso)

## Principios de diseño
- **Alta cohesión, bajo acoplamiento**
- Abstracción, encapsulamiento y ocultamiento de información, modularidad, separación de intereses
- **SOLID**: responsabilidad única, abierto/cerrado, sustitución de Liskov, segregación de interfaces, inversión de dependencias

### Cohesión (de peor a mejor)
coincidental → lógica → temporal → procedimental → comunicacional → secuencial → **funcional**

### Acoplamiento (de mejor a peor)
**datos** → estampado → control → externo → común (globales) → contenido

## Patrones GoF

| Tipo | Patrón | Úsalo cuando… |
|---|---|---|
| Creacional | Singleton | Debe existir una sola instancia global |
| | Factory Method / Abstract Factory | Las subclases o familias deciden qué crear |
| | Builder | Hay objetos complejos que se construyen paso a paso |
| Estructural | **Adapter** | Hay una interfaz incompatible que no puedes cambiar |
| | Decorator | Quieres agregar responsabilidades dinámicamente |
| | Facade | Quieres una interfaz simple para un subsistema complejo |
| | Composite | Hay jerarquías parte-todo (árboles) |
| | Proxy | Necesitas control de acceso, carga diferida o un objeto remoto |
| Comportamiento | **Observer** | Varios objetos deben enterarse de un cambio |
| | **Strategy** | Hay algoritmos intercambiables en tiempo de ejecución |
| | State | El comportamiento depende del estado interno |
| | Template Method | Hay un esqueleto fijo con pasos variables (herencia) |
| | Command | Quieres encapsular peticiones (deshacer, colas) |

## Diseño de datos (relacional)
- Modelo E-R → relacional: entidades, atributos, **cardinalidad** (1:1, 1:N, N:M → tabla intermedia)
- **Normalización**:
  - **1FN**: valores atómicos, sin grupos repetidos, con llave primaria
  - **2FN**: 1FN + sin **dependencias parciales** (con llave compuesta)
  - **3FN**: 2FN + sin **dependencias transitivas** (no clave → no clave)
  - **FNBC**: todo determinante es una llave candidata
- Integridad de entidad (PK) y referencial (FK)

## Datos no relacionales y distribuidos (sobresaliente)

| Modelo NoSQL | Ejemplo | Úsalo para… |
|---|---|---|
| Documental | MongoDB | Esquema variable, agregados que se leen completos |
| Clave-valor | Redis | Caché, sesiones, acceso por llave |
| Columnar | Cassandra | Escrituras masivas, series de tiempo |
| Grafos | Neo4j | Relaciones y recorridos |

- **Fragmentación horizontal** (por filas, se reconstruye con UNION) / **vertical** (por columnas, se reconstruye con JOIN por la llave) / mixta
- **Replicación**: total o parcial; primario-réplica o **multimaestro**; síncrona o asíncrona
- **Teorema CAP**: consistencia, disponibilidad y tolerancia a particiones (solo se pueden garantizar dos ante una partición)
