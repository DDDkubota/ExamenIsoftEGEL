# 4.3 Metodologías de desarrollo (12 reactivos)

## Modelos de proceso tradicionales
| Modelo | Úsalo cuando… |
|---|---|
| **Cascada** | Requisitos estables y bien definidos, equipo grande, comunicación formal |
| **Modelo en V** | Cada fase tiene su prueba correspondiente; dominios regulados |
| **Incremental** | Entregas parciales funcionales; requisitos principales conocidos |
| **Espiral** (Boehm) | Proyecto grande y riesgoso; análisis de riesgos en cada ciclo |
| **Prototipos** | El cliente no tiene claros los requisitos |
| **RUP / Proceso Unificado** | Iterativo y centrado en la arquitectura; fases **Inicio → Elaboración → Construcción → Transición** |
| RAD | Velocidad con componentes reutilizables |

> Ejemplo oficial (ordenamiento): con un **marco tradicional**, el orden es estimación y programación → diseño → código → pruebas → entrega.

## Ágiles
### Scrum (Guía 2020)
- **Responsabilidades**: Product Owner (valor y Product Backlog), Scrum Master (eficacia del equipo, facilitación), Developers (el incremento, el «cómo»)
- **Eventos**: Sprint (≤ 1 mes) · Sprint Planning · Daily Scrum (15 min) · Sprint Review (el producto, con stakeholders) · Sprint Retrospective (el proceso)
- **Artefactos y compromisos**: Product Backlog → Objetivo del Producto · Sprint Backlog → Objetivo del Sprint · Incremento → Definición de Terminado
- Solo el **PO** puede cancelar un Sprint.

### XP
Valores: comunicación, simplicidad, retroalimentación, coraje y respeto. Prácticas: **programación en pares**, **TDD**, integración continua, refactorización, entregas pequeñas, **cliente en sitio**, propiedad colectiva del código, ritmo sostenible.

### Kanban
Visualizar el flujo, **limitar el WIP**, gestionar el flujo (lead time y tiempo de ciclo), políticas explícitas, mejora continua; **no usa iteraciones fijas**.

### Otros
Lean (eliminar desperdicio), Crystal, DSDM (MoSCoW), FDD, OpenUP, SAFe (ágil a escala), DevOps.

## ¿Cómo elegir?
- Requisitos **estables**, equipo grande, control formal → **tradicional** (cascada o V)
- Requisitos **cambiantes**, cliente disponible → **ágil** (Scrum o XP)
- Flujo continuo de soporte → **Kanban**
- Alto riesgo técnico → **espiral** o prototipos
