# 3.2 Paradigmas de programación (10 reactivos)

| Paradigma | Idea | Lenguajes | Pista |
|---|---|---|---|
| Imperativo / **estructurado** | Secuencia, selección e iteración; estado mutable; sin goto | C, Pascal | «funciones, ciclos, if» |
| **Orientado a objetos** | Clases, objetos, encapsulamiento, herencia, **polimorfismo**, abstracción | Java, C#, Python | «misma llamada, distinto comportamiento» |
| **Funcional** | Funciones puras, inmutabilidad, orden superior (map/filter/reduce), recursión | Haskell, Lisp, F#, Elixir | «sin efectos laterales» |
| **Lógico** | Hechos + reglas + consultas; unificación y backtracking | Prolog | «base de conocimiento», «inferir» |
| Orientado a eventos | El flujo lo determinan los eventos (clics, mensajes) | JS en el navegador, GUI | «cuando el usuario…» |
| Declarativo | Se describe *qué* se quiere, no *cómo* | SQL, HTML | |
| Concurrente / reactivo | Hilos, actores, streams | Go, Erlang, RxJS | |

## OO: no confundas
- **Sobrecarga** (overloading): mismo nombre, distintos parámetros, en la misma clase; se resuelve al compilar.
- **Sobrescritura** (overriding): una subclase redefine un método heredado; se resuelve en ejecución (polimorfismo).
- **Clase abstracta vs. interfaz**.
- **Herencia vs. composición** (se prefiere la composición).

## Funcional (sobresaliente)
- `map f xs` aplica f a cada elemento; `filter p xs` conserva los que cumplen p; `foldr`/`reduce` acumula.
- Evalúa de adentro hacia afuera: `map (*2) (filter even [1..10])` = `[4,8,12,16,20]`.
- Evaluación perezosa (Haskell), currificación, funciones de orden superior.

## Lógico (sobresaliente)
```
progenitor(juan, maria).
abuelo(X,Z) :- progenitor(X,Y), progenitor(Y,Z).
```
El motor busca los hechos en orden (de arriba abajo) y retrocede (backtracking) para encontrar más soluciones.
