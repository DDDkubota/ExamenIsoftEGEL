# 3.5 Plataformas de desarrollo (10 reactivos)

## Móvil

| Enfoque | Ventajas | Desventajas | Úsalo cuando… |
|---|---|---|---|
| **Nativo** (Swift, Kotlin) | Máximo rendimiento y acceso total al hardware | Dos bases de código | Hay RA/RV, gráficos o sensores intensivos y presupuesto |
| **Multiplataforma** (Flutter, React Native, .NET MAUI) | Una base de código, rendimiento cercano al nativo | Algunas APIs requieren puentes | Equipo pequeño y tiempo corto |
| **Híbrido** (Ionic/Cordova sobre WebView) | Reutiliza habilidades web | Rendimiento menor | Apps de contenido o formularios |
| **PWA / web responsiva** | No requiere instalación ni tienda | Acceso limitado al hardware, sobre todo en iOS | Alcance amplio, funciones simples |

## Web
- Frontend (HTML/CSS/JS, React, Angular, Vue) / backend (Node, Django, Spring, Laravel, .NET)
- SPA vs. renderizado en el servidor (SSR); APIs REST vs. GraphQL
- Servidores web y de aplicaciones

## Embebidos (sobresaliente)
- Microcontroladores (Arduino, ESP32, STM32), **RTOS** (FreeRTOS, Zephyr) para **tiempo real duro**
- Restricciones de memoria, energía y determinismo; comúnmente C/C++

## Escritorio
- Nativas (WinForms/WPF, Swing/JavaFX, Qt) o multiplataforma (Electron)

## Nube
- **IaaS** (VMs: tú administras el SO) · **PaaS** (subes código) · **SaaS** (usas software terminado) · FaaS/serverless
- Modelos de despliegue: pública, privada, híbrida
