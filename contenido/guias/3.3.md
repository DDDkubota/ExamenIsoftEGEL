# 3.3 Entornos de desarrollo (10 reactivos)

## Herramientas del entorno
- **IDE**: editor, compilador/intérprete, depurador, refactorización (VS Code, IntelliJ, Eclipse, Visual Studio, Android Studio, Xcode)
- **Control de versiones**: Git (commit, rama, merge, rebase, pull request, tag); flujos GitFlow y GitHub Flow
- **Gestión de dependencias y construcción**: Maven/Gradle, npm, pip, NuGet
- **Contenedores**: Docker (imagen, contenedor), orquestación con Kubernetes
- **Ambientes**: desarrollo → pruebas/QA → staging → producción

## DevOps
| Práctica | Qué significa |
|---|---|
| **Integración continua (CI)** | Cada cambio se integra, compila y prueba automáticamente |
| **Entrega continua** | Siempre está listo para liberar; el paso a producción es **manual** |
| **Despliegue continuo** | Lo que pasa el pipeline llega a producción **automáticamente** |
| Infraestructura como código | Terraform, Ansible |

## Calidad del código (sobresaliente: «herramientas de validación del código fuente»)
- **Análisis estático**: linters (ESLint, Pylint), SonarQube, analizadores de seguridad (SAST); revisan el código **sin ejecutarlo**
- **Pruebas dinámicas**: unitarias (JUnit, pytest), integración, sistema, aceptación, carga (JMeter), E2E (Selenium/Cypress)
- **Cobertura** de código; **TDD** (rojo → verde → refactorizar)
- Revisión de código por pares; listas de verificación (McConnell)

## Documentar las pruebas
Plan de pruebas → diseño de casos (entrada, pasos, resultado esperado) → ejecución → reporte de defectos (severidad, prioridad, pasos para reproducir).
Técnicas: **caja negra** (particiones de equivalencia, valores límite, tablas de decisión) y **caja blanca** (cobertura de sentencias, ramas y caminos; complejidad ciclomática V(G) = E − N + 2).

Niveles: **unitarias → integración → sistema → aceptación** (modelo en V).
