# 2.1 Diseño arquitectónico de software (10 reactivos)

## Qué debes poder hacer
Interpretar requerimientos arquitectónicos (de usuario, de restricción y de **atributos de calidad**), elegir estilos o patrones y reconocer métodos de documentación y evaluación.

## Estilos y patrones arquitectónicos

| Estilo | Úsalo cuando… | Costo |
|---|---|---|
| **Capas** (n-tier) | Quieres separar presentación, negocio y datos | Puede penalizar el desempeño |
| **Cliente-servidor** | Hay recursos centralizados y clientes múltiples | El servidor puede ser un cuello de botella |
| **MVC / MVVM** | Interfaces con varias vistas del mismo modelo | Más clases |
| **Microservicios** | Hay equipos autónomos, escalado y despliegue independientes | Complejidad operativa, consistencia eventual |
| **Dirigido por eventos / pub-sub** | Hay muchos consumidores desacoplados que reaccionan a eventos | Flujo difícil de rastrear |
| **Tuberías y filtros** | Se transforman datos en etapas secuenciales (ETL, compiladores) | No es apto para interacción |
| **Repositorio / pizarra** | Varios componentes comparten un almacén central | Acoplamiento al repositorio |
| **Microkernel / plugins** | Producto base extensible (IDE, navegadores) | Gestión de versiones de los plugins |
| **SOA** | Integración empresarial mediante servicios y un bus (ESB) | El ESB centraliza |
| **Serverless** | Cargas esporádicas, pago por uso | Arranque en frío, dependencia del proveedor |

## Documentación: modelo 4+1 de Kruchten
- **Lógica**: la funcionalidad (clases), para usuarios y analistas
- **Desarrollo** (implementación): módulos y paquetes, para los programadores
- **Procesos**: concurrencia, desempeño, distribución en tiempo de ejecución, para los integradores
- **Física** (despliegue): nodos de hardware y red, para infraestructura
- **+1 Escenarios**: casos de uso que validan las 4 vistas

Clements et al. (*Views and Beyond*): vistas de **módulos**, de **componentes y conectores** y de **asignación**. El modelo **C4** (Brown) usa los niveles Contexto, Contenedores, Componentes y Código.

## Atributos de calidad y tácticas (Bass, Clements y Kazman)
- **Disponibilidad**: redundancia, heartbeat, failover
- **Desempeño**: caché, concurrencia, reducir la demanda
- **Seguridad**: autenticar, autorizar, cifrar, auditar
- **Modificabilidad**: alta cohesión, bajo acoplamiento, interfaces
- **Usabilidad**: deshacer, cancelar, retroalimentación

## Evaluación de arquitecturas
- **ATAM**: árbol de utilidad, escenarios, **puntos de sensibilidad** y **de compromiso (tradeoff)**, riesgos
- **SAAM**: escenarios, enfocado en la modificabilidad
- **CBAM**: agrega el análisis costo-beneficio a ATAM
