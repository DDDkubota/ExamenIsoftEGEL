# 3.4 Gestión de datos (9 reactivos)

## SQL que debes poder leer y escribir
```sql
SELECT d.nombre, COUNT(*) AS empleados
FROM Empleado e
JOIN Departamento d ON d.id = e.id_depto
WHERE e.activo = 1
GROUP BY d.nombre
HAVING COUNT(*) > 5
ORDER BY empleados DESC;
```
- Orden lógico: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
- **INNER JOIN** (coincidencias) / **LEFT JOIN** (todas las filas de la izquierda) / anti-join con `LEFT JOIN ... IS NULL` o `NOT EXISTS`
- DDL (CREATE, ALTER, DROP) · DML (INSERT, UPDATE, DELETE, SELECT) · DCL (GRANT, REVOKE) · TCL (COMMIT, ROLLBACK)
- Restricciones: PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK, NOT NULL
- Vistas, índices, procedimientos almacenados, triggers

## Transacciones: ACID
- **Atomicidad**: todo o nada
- **Consistencia**: de un estado válido a otro estado válido
- **Aislamiento**: las transacciones concurrentes no interfieren (niveles: read uncommitted, read committed, repeatable read, serializable)
- **Durabilidad**: lo confirmado persiste

## Tipos de datos (sobresaliente)
- **Estructurados**: tablas con esquema fijo
- **Semiestructurados**: JSON, XML, YAML (autodescriptivos)
- **No estructurados**: imágenes, audio, video, texto libre

## Bases de datos no relacionales y distribuidas (sobresaliente)
- Lenguajes de consulta NoSQL: MongoDB (`find`, aggregation pipeline), CQL (Cassandra), Cypher (Neo4j)
- **BASE** frente a ACID; consistencia eventual; teorema CAP
- **Replicación**: primario-réplica (una sola fuente de escritura; réplicas de lectura) / **multimaestro** (varios nodos aceptan escrituras) / vistas materializadas / síncrona o asíncrona
- **Fragmentación** (sharding): horizontal, vertical, mixta

> Ejemplo oficial: un banco con sucursales que requiere datos actualizados y consultables desde cualquier sucursal (Oracle). Analiza si se pide que *todas* las sucursales escriban (multimaestro) o solo que consulten copias.
